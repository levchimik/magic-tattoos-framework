How it works & gotchas

What gets written. For every .dds the tool finds under textures/, it emits one entry in the catalog with id = label = the filename stem (no extension), a single layer pointing at the texture, and the area you picked.

No previews. Browsers can't render .dds natively; the tool doesn't try. If you want to verify visuals you'll need your usual texture viewer (or just test in-game).

Multi-layer packs. If your pack has a base + glow pair (e.g. actors/.../foo/001.dds + actors/.../foo-glow/001.dds) you'll get two separate entries. Open the generated JSON in a text editor and merge the layers manually — the format is one "layers": […] array per entry, just add the second texture object next to the first. Schema reference.

Renaming entries. Filenames make for ugly MCM dropdowns. Open the JSON and edit the label fields to whatever reads well ("Mark 001" beats "001"). id values must stay unique within the pack but are otherwise free-form.

Privacy. Everything happens in your browser. Your ZIP never touches a server. View page source or open dev tools to verify.
